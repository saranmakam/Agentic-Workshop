- (capability) CAP-1: a triage decision is accepted only as a JSON object with category, priority, route, and a one-sentence rationale. Success: category is billing, bug, access, performance, or how-to; priority is P1, P2, P3, or P4; route is billing-team, bug-team, access-team, performance-team, or how-to-team; rationale is one sentence. A missing field, a value outside those sets, a rationale that is not one sentence, or any other shape is rejected with an error that states what is wrong.
- (capability) CAP-2: a person can load the seed tickets and customers into a local database with one command, and loading again does not change the result. Success: uv run python load_seed.py loads seed/tickets.csv into app.db table tickets and seed/customers.csv into table customers, with the same columns as those files. A second run leaves both tables identical to the first.
- (constraint) Python 3.12 or newer, managed with uv.
- (constraint) Files in seed/ are read-only. The loader reads them and does not modify them.
- (constraint) This epic makes no network calls and uses no API keys.
- (constraint) mcp/triage_server.py already reads app.db. Table tickets keeps columns ticket_id, customer_id, created_at, text. Table customers keeps columns customer_id, name, plan, open_tickets. Those names match the seed CSV headers.
